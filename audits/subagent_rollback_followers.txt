## Tier 1 — papers that actually combine rollback/commit machinery with agent state

**1. SagaLLM: Context Management, Validation, and Transaction Guarantees for Multi-Agent LLM Planning** — Edward Y. Chang (co-first, Stanford), Longling Geng; 2025; arXiv preprint (v3). https://arxiv.org/abs/2503.11951 (abstract fetched).
Saga transactional pattern over multi-agent LLM planning: persistent memory, modular checkpointing, automated **compensation**, **independent validation agents**, compensable execution, dependency analysis, recovery orchestration. (a) PARTIAL — rolled-back state is shared workflow state containing *actions* committed by prior agent steps (compensation can undo another agent's committed effects); it is not peer *information* mutating a reasoning state, and there is no exposure-before-commit of peer info. (b) NO — state mutates and is compensated post hoc; no immutable incumbent preserved during exposure. (c) PARTIAL — compensation/dependency logs. (d) YES — explicit validation agents + compensable execution. (e) YES — multi-agent planning core (workflow, not deliberation).

**2. ALAS: A Stateful Multi-LLM Agent Framework for Disruption-Aware Planning** — Edward Y. Chang; 2025; arXiv (ACM DL version Dec 2025 per search, UNVERIFIED). https://arxiv.org/abs/2505.12501 (abstract fetched).
Role-specialized agents, automatic state tracking, history-aware **local compensation** on disruptions, avoiding global replanning. (a) PARTIAL (perturbation-induced, not peer-info); (b) NO; (c) PARTIAL; (d) PARTIAL (compensation protocol, not an explicit commit validator); (e) YES (multi-agent planning). Same Stanford lineage as SagaLLM.

**3. REVISE: Validity-Guided Recovery for Online Revisions in Agent Workflows** — 2026; arXiv preprint. https://arxiv.org/abs/2609.00643 (abstract fetched).
When a revision arrives mid-execution, REVISE "intersects its **delta** with recorded data and control dependencies," propagates impact through the partially executed DAG, stops invalid work, **preserves validity-established incumbent progress**, recomputes only the affected region, and "reused results are **revalidated before commit**." (a) PARTIAL — the transition is induced by an externally arriving revision (a later queued message), not by a peer agent's reasoning contribution. (b) YES — unaffected incumbent work preserved. (c) YES — delta explicitly intersected with dependencies. (d) YES — commit-time revalidation. (e) NO — single-workflow runtime (LangGraph/LLMCompiler), not multi-agent reasoning. **Mechanically the closest to the SCD chain (b)(c)(d), but in the wrong domain.**

**4. TomasuLLM: Out-of-Order Speculative Execution for LLM Agents** — Jiangnan Yu et al.; 2026; arXiv preprint. https://arxiv.org/abs/2609.38201 (abstract fetched via full page).
Speculative out-of-order tool-call execution: drafts future actions, runs them in **isolated copy-on-write sandboxes**, traces dependencies, and "commits results in trajectory order **only after validation against committed state**" (4,010 audited commit-validation records, zero false accepts). (a) OWN — single agent's own actions; no peer state anywhere in the abstract. (b) YES analogue — committed state + copy-on-write isolation. (c) YES analogue — speculative drafts kept separate from committed trajectory. (d) YES — explicit commit validator. (e) NO. **This is the SCD speculative-commit pattern realized for tool calls of a single agent — the nearest structural neighbor, still not peer-induced and not reasoning state.**

**5. When Can Agents Safely Checkpoint, Fork, Restore, and Merge? Exact Checking for Execution Edits** — Yusheng Zheng et al.; 2026; arXiv preprint. https://arxiv.org/abs/2608.22928 (abstract fetched).
Runtime-level Checkpoint/Fork/Restore/Merge ("execution edits") with an **exact decider** of edit safety; returns all safe continuations or a Lean-mechanized proof that none exists; handles atomic enforcement. (a) OWN — runtime edits of one agent's execution. (b) YES — checkpoint preserves incumbent. (c) PARTIAL — branches as separate executions. (d) YES — the strongest formal COMMIT/ROLLBACK validator found anywhere in this pass. (e) NO.

**6. When AI Agents Commit: Cognitive Serializability Across Data, Evidence, Policy, and Authority** — Jun He; 2026; arXiv preprint. https://arxiv.org/abs/2609.20261 (abstract fetched).
Commit semantics for agent mutations whose **derivation inputs (data, evidence, policy, authority) may change while reasoning is in progress**: immutable versioned executable definitions, typed dependency tokens, guard-first commit transactions, co-committed receipts, serializability conditions. (a) PARTIAL — inputs can be changed externally (including by other agents' writes), but the problem is stale derivation, not adopting/retracting a peer's communicated information. (b) YES for versioned immutable definitions. (c) PARTIAL (dependency vectors). (d) YES — explicit commit contract with serializability. (e) NO — transaction-processing runtime, single-agent-centric.

## FINAL VERDICT

**No paper found applies rollback to a state changed by another agent's information in multi-agent LLM reasoning.** The SCD five-factor chain (peer-induced transition + immutable incumbent during exposure + separately represented delta + explicit COMMIT/ROLLBACK validator + multi-agent reasoning core) remains unclaimed. The gap is real but *crowded at the borders*, in three schools, each missing different factors:

1. **Transaction/compensation school** (SagaLLM, ALAS, Mnemosyne, Janus): has (d) and (e), but rollback is post-hoc compensation of external workflow effects — (a) only in the action sense, (b) and (c) fail.
2. **Runtime recovery school** (REVISE, TomasuLLM, the Checkpoint/Fork/Restore/Merge exact checker, Planarian, AgentRewind, CoAgent): has (b), (c), (d) mechanically — including an exact, machine-checked commit validator — but everything is a single agent's own execution or tool effects; (a) peer-*information*-induced transitions and (e) multi-agent reasoning both fail. TomasuLLM is the single closest structural template (speculative + copy-on-write + validate-then-commit) applied to tool calls only.
3. **Deliberation/belief school** (ECON, ICML 2025): has peer-induced belief transitions in multi-agent reasoning (a-partial, e) but no rollback, no immutability, no validator.

**Closest single paper overall: REVISE (2609.00643)** — 4 of 5 factors (b, c, d, plus externally-triggered transition) but in a coding-workflow runtime where the trigger is a user revision, not a peer agent's reasoning contribution. **SCD's specific composition — speculative branches of a peer-changed social/belief state against an immutable incumbent, gated by an explicit COMMIT/ROLLBACK validator inside multi-agent reasoning — is not present in the 2024–2026 literature I could reach.**

Caveats: OpenReview full-text search is not externally crawlable (only site-restricted Google queries + the one ICML 2026 position paper found); DBLP was bot-blocked; items marked "title only" or "search-verified" above were not abstract-verified. Within those limits, no near-duplicate was missed.
